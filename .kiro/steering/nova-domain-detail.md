## 백엔드 아키텍처 계층 구조 (Confluence 기준)

### L1 ~ L5 계층

| 계층 | 업무 기능 항목 (BSF) | 논리 구성요소·설계 | 물리 구성요소·기술 구현 |
|------|---------------------|-------------------|------------------------|
| L1 도메인 | 서비스 조직 경계(서비스 후보) | 도메인 Boot Service - 독립 저장소 | Spring Boot Service - 독립 저장소 |
| L2 컴포넌트 | 컴포넌트 | 컴포넌트 개별 포트노드 - 독립 저장소 | Gradle 서브프로젝트 - 개별 JAR / Contract JAR |
| L2.5 서브컴포넌트 | 서브 컴포넌트 - 기술 모듈 | 서브 컴포넌트 기술 모듈 | Gradle 서브프로젝트 - 기술 JAR |
| L3 업무 | 비즈니스 모듈 | 비즈니스 모듈 | Java 패키지 `{businessmodule}` |
| L4 기능 | Operation Interface | Operation Interface | Java interface 세트 |
| L5 상세 기능 | Application Service, Domain, Port, Adapter | Application Service, Domain, Port, Adapter | Java class / record |

### 주문 접수 구조 예시 (Confluence)
```
컴포넌트: 주문
  └─ 서버 컴포넌트: 주문 접수
       ├─ 비즈니스 모듈: 주문 등록
       │    ├─ Contract: RegisterOrder 계약
       │    ├─ Core: 주문 등록 (업무/도메인/Persistence 책임)
       │    └─ Presentation: 주문 등록 Open API
       └─ Orchestration: 주문 접수 후 결제 준비 흐름
            └─ Client REST: 결제 준비 Contract 환경 Binding
```

### 구조 판별 근거
| 구조 항목 | 예시 판명 | 판명 근거 |
|---|---|---|
| 컴포넌트 | 주문 | 주문 업무 능력과 주문 데이터 변환을 소유함 |
| 서브 컴포넌트 | 주문 접수 | 접수 생명주기와 정책이 주문 조회·사후 처리와 구분됨 |
| 비즈니스 모듈 | 주문 등록 | 등록 상태변화 데이터 변경 Test가 하나의 변경 이유로 담힘 |
| Contract | RegisterOrder 계약 | 다른 컴포넌트가 주문 등록을 오지힘 |
| Core | 주문 등록 Application·Domain·Persistence 책임 | 단일 업무 규칙과 주문 데이터 변환을 소유함 |
| Presentation | 주문 등록 Open API | 슈피니 채널이 HTTP로 주문 등록을 요청함 |
| Orchestration | 주문 접수 후 결제 준비 흐름 | 주문과 결제 준비 서비스 순서·산화 절차에 따라 조합함 |
| Client REST | 결제 준비 Contract 환경 Binding | 결제 목적이 다른 실행 단위에 있음 |

### 물리 구성요소 구조도
```
presentation         contract-rest        boot
[Controller]  →  [Contract Class Adapter]  →  [Boot Application]
```

### 핵심 규칙
- L1 ~ L2.5: 저장소 프로젝트 경계 (3~15개 마치까지 매치트로 나타남)
- Port는 컴포넌트 내에서 다음 기술 모듈로 포표로 포고 기술 의존은 Port로 역전됨
  - Port는 연부가 필요로 하는 기술 응용: 세계 나라에서 안쪽으로 포표고, Adapter는 Port의 기술 구현체

## 개발 협업 컨벤션

### 우리 팀 원칙
- 두 개발자(나 + Kiro)가 함께 설계·구현을 진행
- 도메인 구현 순서: 수납정책 → 청구계정/납부계정 → 인출일정/계획 → 즉시납부 → 수납/수납상세 → 수납연계 → 수납기준
- 엔티티 설계 전 사진/문서 내용을 충분히 논의 후 구현
- Spring Boot + JPA + MySQL 8.0 기반
- 패키지: `com.nova.domain.{도메인명}.{계층}`
- DB: `nova_db` / Host: `localhost:3306` / User: `P215138`

### 코드 작성 기준
- Entity: `@Entity`, `@Table`, JPA 어노테이션 사용
- 복합 PK: `@EmbeddedId` 또는 `@IdClass` 사용
- 멀티테넌트: 모든 엔티티에 `tenantId` 필드 필수
- JSON 속성: `@Column(columnDefinition = "JSON")` 또는 `@Convert` 사용
- API 응답: `ApiResponse<T>` 래퍼 사용
- 예외: `BusinessException` 사용
