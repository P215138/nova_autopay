# 납부수단 비즈니스 규칙 정의서

> 사진 기반 정리 - NOVA 수납 도메인 (청구계정 / 납부수단 / 납부계정)

---

## 1. 정리

### 계약
- **정의:** 고객이 실제로 이용하는 통신 서비스 (예: 5G 스마트폰 회선, 기가인터넷)
- **역할:** "무엇을 이용하고 있는가?"를 정의합니다.

### 청구계정
- **정의:** 고객에게 매월 발송되는 청구서의 기준 단위(채권 관리). 1개의 청구계정 안에 여러 개의 핸드폰, 인터넷 회선이 담길 수 있음.
- **역할:** "누구에게 얼마를 받을 것인가?"를 정의합니다. (하나의 청구계정 안에 가족 4명의 계약도 모두 담을 수 있습니다.)
- **특성:**
  - 이번 달 청구서를 어떤 형태로 발송할지(지로, 자동이체 안내 등)를 결정하는 납부방법코드(01~05)가 기입된다.
  - 인출일을 고객이 선택할 수 있음. 시스템에서 제공하는 고정일자 옵션 리스트(예: 10일, 13일, 15일, 21일 등) 중 선택.

### 납부수단 (지갑)
- **정의:** 고객이 소유한 순수한 '금융 결제 수단'(신용카드, 은행계좌, 간편결제 등)입니다.
- **역할:** "어떤 도구(수단)를 가지고 있는가?"를 정의합니다. 아직 어디에 쓸지 정해지지 않은 상태로, 마이페이지 지갑에 보관된다.
- **특이점:** 청구계정(개인)이나 계약(회선)에 종속되지 않고 존재합니다. 고객은 가입된 통신 상품이 없어도 앤 회원자격만으로 지갑에 수단을 미리 등록해 둘 수 있습니다.
- **유형정보:** 사실상 수단이 N개로 존재하는 사실입으로는 결제 금액(승인) 값이 발생하지 않습니다. 교체는 반드시 이 수단을 '납부계정(Pay Plan)'에 매핑함으로 관리 되어야 한다.
- **범위:** 타인 명의의 계좌/카드도 등록 가능. 단, 계좌주/카드주에 대한 2차 인증이 필요할 수 있음.
- **[확인필요]** 타인명의 등록 시 2차 인증의 구체적 방식 및 범위 정의 필요.

### 납부계정 (자동납부 약정서)
- **정의:** 특정 청구계정(BA) 또는 선불계약의 요금을, 특정 납부방법(Mthd)으로 매월 인출하겠다는 '자동납부 동의서/약정서'입니다.
- **역할:** "어떻게, 어떤 돈을 뺄 것인가?"를 정의합니다. 외부 금융기관(PG/VAN)의 등록/발급된 원장 or 출납 키(Bill-key)를 보관합니다.
- **생성 조건:**
  - **후불계약:** 청구계정에 자동이체 납부방법 신청 시 생성
  - **선불계약:** 정기결제 신청 시 생성

### 즉시결제 / 보조결제
- 납부계정 내에 설정하는 인출 순서. 주결제(배치 인출) 실패 시, 보조결제로 실시간 즉시 결제를 시도하여 미납을 방지함.

### 납부계정의 인출유형 (시스템 결정, 고객과 무관)
- **은행:** EDI / FB / CMS → 파일로 인출요청
- **간편결제:** 실시간 간편결제 승인요청
- **카드:** 카드승인요청 → 파일로 인출요청
- **단, 에버라인 즉시결제 시에는 카드도 실시간 승인 가능**

## 2. 비즈니스 rule

### 1) 고객 1명은 N개의 계약, N개의 납부수단, N개의 납부계정, N개의 청구계정을 가질 수 있다.

**EX)**
- A고객은 계약1로 핸드폰+스마트워치를 계약했다. 계약2는 인터넷+BTV 계약을 했다.
- 계약1은 청구계정1로 요금을 납부하도록 설정. 계약2는 청구계정2로 요금을 납부하도록 설정.
- 납부수단으로는 기업은행계좌 1개(납부수단1)와 하나카드 1개(납부수단2)를 등록하여 총 2개의 납부수단을 등록했다.
- 청구계정1은 자동납부로 납부하기 위해서 납부수단1로 납부하기 위해 납부계정1을 생성하였다.
- 청구계정2는 자동납부로 납부하기 위해서 납부수단2로 납부하기 위해 납부계정2를 생성하였다.

### 2) 납부계정 매핑 관계

| 유형 | 관계 |
|------|------|
| 후불 | 청구계정 ↔ 납부계정 1:N |
| 선불 | 계약번호 ↔ 납부계정 1:N |

### 3) 납부계정에는 납부수단이 1:N으로 매핑된다.

**EX)**
- 납부계정에는 메인납부수단과 예비납부수단을 각각 가지고 있을 수 있다.
- 고객B에게 납부수단X(은행계좌) / 납부수단Y(신용카드)를 지갑에 가지고 있다.
- 고객B는 요금납부를 자동납부로 납부하기 위해서 납부계정을 생성하면서 납부계정의 메인납부수단을 납부수단X로, 예비납부수단은 납부수단Y로 설정하였다.

### 4) 자동납부 정기결제 진행 시 메인납부수단으로 인출요청을 하게 되고, 인출이 오류처리될 경우 예비납부수단으로 즉시결제 처리를 진행한다.

### 5) 청구계정의 명의는 꼭 해당 고객의 명의가 되는 건 아니다.

**EX)**
- 고객C는 미성년자 고객으로 계약3으로 핸드폰을 계약 중이다.
- 계약3의 요금은 아버지의 청구계정인 청구계정1에 연결하여 요금을 납부한다.

## 3. 고객여정

1. 고객이 대리점/웹/앱 등 서비스를 가입하러 간다.
2. 서비스는 선불/후불로 금액을 자불할 수 있음.
3. 선불은 구독형식이다. (5월 10일 결제 먼저 진행 → 서비스 이용기간 만료 → 6월 10일 결제 → 서비스 이용기간 만료 ...)
4. 후불은 후청구구독이다. (서비스계약 성립(5월 10일) → 서비스 이용기간 만료 → 5월 말일자로 서비스 이용기간에 대한 요금을 계산하여 청구)
   - 고객선대 인출일에 청구금액 인출 → 6월 납입 이용기간에 대한 요금을 계산하여 청구 → 고객선대 인출일에 청구금액 인출
5. 계약 이후 선불(구독)으로 진행하는 경우 청구계정을 생성하지 않고 납부수단을 등록/납부계정을 생성하여 납부계정에 연결된 납부수단으로 정기결제를 할 수 있다.
   - 선불 인출일: 계약일 기준 매월 동일일로 고정 (추정)
   - **[확인필요]** 선불 정기결제 인출일이 계약일 기준 고정인지 확정 필요. (최지 시 잔여기간 환불 정산 근거)
6. 계약 이후 후불로 진행하는 경우 청구계정을 생성하고 자동납부로 진행한다면 납부수단을 등록/납부계정을 생성하여 연결된 납부수단으로 정기결제를 진행한다.
