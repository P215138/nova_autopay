## 1. 개요 & 범위

**납부수단(PAY_MEANS)** = 고객이 소유한 순수 결제수단(지좌/카드/간편결제). "지갑"

| 포함 (paymeans 책임) | 제외 (타 도메인) |
|---|---|
| 수단 지갑 정보 (계좌/카드정보, 유효기간) | 약정(수단↔청구계정에 언제 → registration) |
| 단순 실시간인증 (본인, 은행/카드) → extauth 소유 | 연동 수단인 · 요청요청 · 인출이력 → extauth |
| 카드BIN 등록·보정 (CardBinRegistrar, 유효성검증 소유) | 실시간 원장등록 인증 → registration + extauth |
| 대리납부 협업 (요청·중단·조회) | 예비수단 사용 시 인출 → registration |
| 예타수단 ( backpaymeans ) → 정규개별 기준, 약정 특립 (4.12.7) | 인출실행, 배치설계 → withdrawal |
| 지갑 CRUD (등록/조회/변경/사용중지/사용종료) | 인출 실행 → withdrawal |

**핵심 룰 [BR-1 비실행성]:** 지갑 등록만으로는 인출 안 됨. PAY_ACCT(약정) 매핑 시부터 결제 발생.

## 3. 상태 모델 (납부수단상태코드) [OI-8 초안 확정]

**auth-first 원칙:** 실시간인증을 먼저 수행하고 인증 결과에 따라 PAY_MEANS 저장 여부/상태를 정한다. AS-IS 인증구분(auth_cl_cd) 3분기[1 내부인증=이력 재사용 / 2 외부인증=실시간인증(신규) / 3 무연동=금융기관 원장에 SKIP]을 계승한다. (docs/분석자료/AS-IS_유스케이스_분석.md).

- 동기 성공(SUCCESS/SKIP) — 내부인증·외부인증 즉납상태) 균납로 10(활성)으로 저장.
- 동기 실패/STOP(외부인증 실패): 저장하지 않고 오류를 반환한다(행 자체가 생기지 않음). **실시간인증 실패로 인한 종료(40)은 발생하지 않는다.**
- 금융기관 장애·비동기(무연동 3 / 외부인증 지연): 02(인증대기)로 저장하고, 장애 해소 후 배치(ZAPABCRT00020→00030)/폴백 후속처리로 02→10(활성) / 최종 실패 시 02→40(종료)로 전이한다.
- 대리납부(비대면): 실시간인증 성공분 01(등록중)로 저장하고 소유주 SMS 동의를 대기한다(U104→U105).

```
[실시간인증 먼저 수행] (auth_cl_cd: 1 내부 / 2 외부 / 3 무연동)

동기성공 ─── 동기실패/STOP ─── 금융기관 장애·비동기(무연동/지연)
   │            (저장 안 함, 오류 반환)       │  → [02 인증대기]
   │                                          │    배치(ZAPABCRT00020→00030)/폴백 후속처리
   │                                     외부호출 ───── 인출불가/가입요구
   │                                        │ → [10 발성]  → [40 종료]
   │
   ├─ 본인명의 ────────────────→ [10 활성]
   ├─ 대리·부인(비대면) → [01 등록중] (소유주 동의 대기) → 소유주 동의 완료(U10)
   │        │                                                  │
   │      승인                                             가절/지연
   │   → [10 활성]                                     → [40 종료] (동의거부/동의지연)
   │
   ├─ 사용중지 → [20 사용중지]  (신규 매출자 차단, 기존 PAY_ACCT 뉴지 [OI-b])
   │              저활성
   │
   └─ 해지 → [30 해지]  (매핑 PAY_ACCT 전부 배지 부탄 가능)
```

### 3.1 납부수단상태코드 (MEANS_STAT_CD)

| 코드 | 상태 | 의미 | 인증 가능 |
|---|---|---|:---:|
| 01 | 등록중 | 실시간인증 성공 후 대리납부(비대면) 소유주 동의 대기 | ○ |
| 02 | 인증대기 | 금융기관 장애·비동기 인증(무연동 3) · 배치(폴백 인증분비) 내지 | ○ |
| 10 | 활성 | 시간에 해소 되뜸 [소시간인증 완료] | (액티 태점세서) |
| 20 | 정지 | 신규 매핑 차단 (기존 유지) | × (기존 태점밖어) |
| 30 | 해지 | 논선 삭제 (soft delete) | × |
| 40 | 종료 | 대리납부 소유주 미용의동(동의거부/동의지연) 또는 인증대기 실패 (최종 상태/타임아웃) | × |

> **01(등록중)** 은 대리납부 비대면 전용(소유주 동의 대기). **02(인증대기)** 는 금융기관 장애·비동기 대기(무연동 포함) — 둘 다 내부 사유가 다르므로 구분한다. 논선명의 등록시 01만 등등 성성 후 소유 → 10 임의로 저장하며, 팀백STOP시 저장(대리 없음). 실시간인증(성공 배치)에 따라 02 저장에 배지/(폴백 후속처리)를 진다/다. **40(종료)** 발성 정보: U9 대리납부 소유주 동의 거부/지연, 실시간인증 실패는 예초에 서양비되 필요으로 40 대상은 아니다.

(상이코드 02X 사이코드 02는 별도 체계로 값이 검토도 부발하다). 종료(40)로 가는 사유: 소유주 거부(41)·동의지연(42), [대리납부] 인출은 (최종 실패 상태), 감정시간 정체된다.

### 4.1 대리납부(타인명의) 등록 흐름 — 비동기 승인 (요청 → 후속 완료)

동의서로는 토큰 방식 X. 실시간인증을 먼저 수행하고 성공한 경우에만 등록중(pending) 상태로 저장, 소유주 동의 완료 후 후속 활성화. (auth-first)

```
[STEP 1 - 요청 (대리납부자=피용자)]
  U9  대리납부 등록 요청
    ├─ 단순 실시간인증(A1/A2) 선행 수행
    │    · 실패/STOP: PayMeans 저장 안 함, 오류 반환 (행 없음) → 종료
    │    · 인증/SKIP: 신규 발생함
    ├─ PayMeans 생성 (상태 = 01 등록중) → 지갑 신관용함
    ├─ AgentPayMap 생성 (상태 = 요청)
    ├─ 소유주(대리납부자)에게 동의요청 발송 (SMS/알림)
    └─ 사후에게는 "수요청(소유 대기)"에 응답, 즉시 X됨.

[STEP 2 - 동의 완료 (수단 소유주=대리납부자, 후속 시간)]
  U10 [대리납부 동기 완료 사후 시간]
    ├─ (실시간(코드 = UNK)로 UNK내 완결능→ 후속인증 없음)
    ├─ 수신함: PayMeans 활성(01) + AgentPayMap 활성
    └─ 거절: PayMeans 종료(40), 사용 비, 소유 유효값을 거강? + AgentPayMap 거절

[완료-후 방지]
  · 두 곳 바치가 상적, U9 경로 시 AgentPayMap 완료 + PayMeans 종료(01→ 유효 사유 40 유(지반/완료) → 강료, 배치)
```

- **auth-first:** 실시간인증을 U9(요청) 사점에 먼저 수행하고, 성공한 수단만 등록중(01)으로 저장한다. U9은 동배(선불 저장A시 없음 [저장으로 "실시간인증 실패로 인증 없는" 상태]가 없다.
- **비능기: 요청(U9)과 완료(U10)는 다른 시점 · 다른 주체.** 서비/트은으로 로시 않음. U10은 소유주 동의 후 별도 유효호변 편집한다.
- **상태코드 관리:** 각 경로마다 아루 패니 동의 유효상태 처리 (앱 열림/일괄 재저장).
- **재인증 가능:** 소유주 거절해도 이후 재요청 가능 (앱 열림 시점).
- **동의 후속:** 목의요청은 반드시 수단 소유주(대리납부자)에게 서로 전송.
- **미완료 정리:** 배선 완료(TTL) 지나면 완료 배치로 정지 기간을 후 정리(종료 40, 사유 42).

### 4.2 본인명의 등록 흐름 — auth-first + 금융기관 장애(비동기) 처리

## 5. 인증 어댑터 (단순 실시간인증)

원장등록 없는 유효성 검증만. EAI/EIGW 경유.

| A3. 대리납부 동의요청 발송 | SMS/알림 발송사 | 소유주 휴대폰번호 + 동의요청 링크 | paymeans ( SmsAuthAdapter ) | 신규 (U9) |

| AS-IS | 실제 | TO-BE |
|---|---|---|
| zapamcom10020 | 계좌번호 자리수·과목코드·체크디지트 (은행별 100여 규칙, DBIO 1건) | [SHARED]/domain/policy/BankAccountFormatValidator |

> 즉 로컬 형식검증(shared) → 외부기관 인증(extauth) → 이력 기록(extauth) 3단계이며, paymeans는 요청만 한다.

- **간편결제(05):** 별도 인증 없이 본인확인만으로 등록 (대리납부 불가).
