> **도메인**: `paymeansregistration` (납부수단 등록/관리)

## 1. Spring Boot 핵심 개념 — 이 프로젝트에서 쓰이는 것만

### 1.1 의존성 주입 (DI) — Spring의 핵심

**자바 방식:**
```java
public class PayMeansCoreApiController {
    private PayMeansRegistrationService service = new PayMeansRegistrationService();
}
```
문제: Controller가 Service 생성을 직접 관리. 테스트 어렵고, 결합도 높음.

**Spring Boot 방식:**
```java
@RestController
public class PayMeansCoreApiController {
    private final PayMeansRegistrationService registrationService;
    
    public PayMeansCoreApiController(PayMeansRegistrationService registrationService) {
        this.registrationService = registrationService;
    }
}
```

- Spring이 `PayMeansRegistrationService` 객체를 **생성해서 주입**해 줌
- Controller는 "누가 만들어준 Service"를 받기만 함 (생성 책임 X)
- `final` + 생성자 주입 = Spring 권장 패턴 (불변성 보장)

### 1.2 @어노테이션 — Spring에게 역할 알려주기

| 어노테이션 | 의미 | 스프링이 하는 일 |
|-----------|------|-----------------|
| `@RestController` | REST API 컨트롤러 | 이 클래스를 Spring Bean으로 등록, HTTP 요청 처리 |
| `@RequestMapping("/path")` | 이 클래스의 기본 URL 경로 | `/api/autopay/pay-means`로 시작하는 요청 매핑 |
| `@PostMapping` | HTTP POST 요청 처리 | 이 메서드가 POST 요청 핸들러 |
| `@RequestBody` | 요청 JSON → Java 객체 변환 | Jackson이 자동 역직렬화 |
| `@Service` | 서비스 계층 | Spring Bean 등록, 트랜잭션 관리 대상 |
| `@Transactional` | 트랜잭션 경계 | 메서드 실행 중 예외 발생 시 DB 롤백 |
| `@Mapper` | MyBatis 매퍼 인터페이스 | 구현체 자동 생성, SQL 실행 |

### 1.3 Spring Bean 생명주기

```
앱 시작
  → Spring이 @RestController, @Service, @Mapper 붙은 클래스 스캔
  → 객체 생성 (싱글톤)
  → 생성자 파라미터 보고 의존성 주입
  → 준비 완료
  → HTTP 요청 오면 Bean 재사용
```

**중요**: Controller, Service는 **싱글톤** (앱에 1개만 존재). 요청마다 새로 만들지 않음.

## 2. 헥사고날 아키텍처 — Port와 Adapter

### 2.1 전통적인 계층형 (우리가 아는 방식)

```
Controller → Service → Repository(Mapper) → DB
```
문제: Service가 MyBatis Mapper에 직접 의존 → DB 기술 바꾸면 Service도 수정

### 2.2 헥사고날 아키텍처 (이 프로젝트)

```
Controller → Service → Port(인터페이스) ← Adapter(구현체) → DB
                                      ← Adapter(구현체) → 외부 API
```

**핵심 아이디어:**
- Service는 **Port(인터페이스)**에만 의존
- Adapter는 Port를 구현해서 **실제 기술**(MyBatis, REST, 메시지큐) 처리
- Service는 DB가 MySQL인지 MongoDB인지 몰라도 됨

### 2.3 우리 프로젝트의 Port

```java
// application/port/PayMeansRepositoryPort.java (인터페이스)
public interface PayMeansRepositoryPort {
    PayMeans save(PayMeans payMeans);
    Optional<PayMeans> findById(Long payMeansNo);
    List<PayMeans> findByOwner(String tenantId, Long customerNo);
}
```

**Port = 서비스가 필요한 기능의 계약서**

### 2.4 우리 프로젝트의 Adapter

```java
// infra/persistence/repository/PayMeansRepositoryAdapter.java (구현체)
@Component  // ← Spring Bean으로 등록
public class PayMeansRepositoryAdapter implements PayMeansRepositoryPort {
    private final PayMeansMapper mapper;  // MyBatis
    
    @Override
    public PayMeans save(PayMeans payMeans) {
        PayMeansEntity entity = PayMeansEntity.from(payMeans);
        mapper.insert(entity);
        return payMeans.withAssignedNo(entity.getPayMeansNo());
    }
}
```

**Adapter = Port 인터페이스를 MyBatis로 실제 구현**

### 2.5 Service는 Port만 안다

```java
@Service
public class PayMeansRegistrationService {
    private final PayMeansRepositoryPort repository;  // 인터페이스
    private final AccountVaultPort vault;             // 인터페이스
    private final FinancialAuthGatewayPort authGateway;  // 인터페이스
    
    // 생성자 주입: Spring이 Adapter 구현체를 주입해 줌
    public PayMeansRegistrationService(
        PayMeansRepositoryPort repository,
        AccountVaultPort vault,
        FinancialAuthGatewayPort authGateway
    ) {
        this.repository = repository;
        this.vault = vault;
        this.authGateway = authGateway;
    }
}
```

**Service는 Adapter의 존재를 모름. Port 인터페이스만 봄.**

## 3. 납부수단 등록 흐름 — Spring Boot 관점

### 3.1 HTTP 요청부터 DB까지

```
POST /api/autopay/pay-means
{
  "tenantId": "SKT",
  "customerNo": 9000000001,
  "payMeansType": "BANK",
  "accountOrCardNo": "1002123456789"
}
```

#### ① Controller — HTTP 요청 받기

```java
@RestController
@RequestMapping("/api/autopay/pay-means")
public class PayMeansCoreApiController {
    private final PayMeansRegistrationService registrationService;
    
    // Spring이 생성자 주입으로 Service를 넣어줌
    public PayMeansCoreApiController(PayMeansRegistrationService registrationService) {
        this.registrationService = registrationService;
    }
    
    @PostMapping  // POST /api/autopay/pay-means
    public ApiResponse<PayMeansView> register(
        @RequestBody RegisterPayMeansCommand command  // JSON → Java 객체 자동 변환
    ) {
        PayMeansView view = registrationService.registerByOwner(command);
        return ApiResponse.success(view);
    }
}
```

**Spring Boot의 역할:**
- `@PostMapping` → 이 메서드를 HTTP POST 핸들러로 등록
- `@RequestBody` → JSON을 `RegisterPayMeansCommand` 객체로 변환 (Jackson)
- 반환값 `ApiResponse<PayMeansView>` → 자동으로 JSON 응답 생성

#### ② Command 객체 — 불변 DTO

```java
public record RegisterPayMeansCommand(
    String tenantId,
    Long customerNo,
    PayMeansType payMeansType,
    String accountOrCardNo,
    String bankCode,
    String ownerNm
) {}
```

**Java 14+ record:**
- 자동으로 생성자, getter, equals, hashCode 생성
- 필드가 모두 `final` (불변)
- Spring은 record도 `@RequestBody`로 받을 수 있음

#### ③ Service — 비즈니스 로직

```java
@Service
@Transactional  // ← 이 메서드는 트랜잭션 안에서 실행
public class PayMeansRegistrationService {
    private final PayMeansRepositoryPort repository;
    private final AccountVaultPort vault;
    private final FinancialAuthGatewayPort authGateway;
    private final RealtmAuthHistoryPort authHistory;
    
    public PayMeansView registerByOwner(RegisterPayMeansCommand command) {
        // 1. 금융기관 실시간 인증 (외부 API)
        FinancialAuthResult authResult = authGateway.authenticate(
            new FinancialAuthRequest(
                command.payMeansType(),
                command.accountOrCardNo(),
                command.bankCode(),
                command.ownerNm()
            )
        );
        
        if (!authResult.isSuccess()) {
            throw new IllegalStateException("금융기관 인증 실패: " + authResult.message());
        }
        
        // 2. 계좌/카드번호 암호화 저장 (금고)
        Long alternateId = vault.store(command.accountOrCardNo());
        
        // 3. 납부수단 도메인 객체 생성 (정적 팩토리 메서드)
        PayMeans payMeans = PayMeans.registerByOwner(
            command.tenantId(),
            command.customerNo(),
            command.payMeansType(),
            alternateId,
            command.bankCode()
        );
        
        // 4. DB 저장 (Port를 통해)
        PayMeans saved = repository.save(payMeans);
        
        // 5. 인증 이력 저장
        authHistory.createRequested(...);
        authHistory.applyResult(...);
        
        // 6. 조회용 View 객체 반환
        return PayMeansView.from(saved, vault);
    }
}
```

**Spring의 `@Transactional`:**
- 메서드 시작 시 트랜잭션 시작
- 메서드 정상 종료 시 커밋
- 예외 발생 시 **모든 DB 변경 롤백**
- `authHistory.createRequested()`만 예외: `@Transactional(REQUIRES_NEW)` → 별도 트랜잭션

#### ④ Domain 객체 — 비즈니스 규칙

```java
public class PayMeans {
    private Long payMeansNo;
    private String tenantId;
    private Long ownerCustomerNo;
    private PayMeansType payMeansType;
    private PayMeansStatus status;
    private Long accountOrCardAlternateId;
    private String bankCode;
    
    // 정적 팩토리 메서드 (생성자 대신)
    public static PayMeans registerByOwner(
        String tenantId,
        Long ownerCustomerNo,
        PayMeansType payMeansType,
        Long accountOrCardAlternateId,
        String bankCode
    ) {
        // 비즈니스 규칙: 본인 등록은 즉시 활성
        return new PayMeans(
            null,  // DB에서 채번
            tenantId,
            ownerCustomerNo,
            payMeansType,
            PayMeansStatus.ACTIVE,  // ← 본인 등록이므로 활성
            accountOrCardAlternateId,
            bankCode
        );
    }
    
    // 상태 전이 메서드
    public void suspend() {
        if (this.status != PayMeansStatus.ACTIVE) {
            throw new IllegalStateException("활성 상태만 정지 가능");
        }
        this.status = PayMeansStatus.SUSPENDED;
    }
}
```

**도메인 주도 설계(DDD) 패턴:**
- 생성자 private, 정적 팩토리 메서드 public → 생성 규칙 강제
- 상태 변경은 메서드를 통해서만 (`suspend()`, `resume()`)
- **도메인 객체가 비즈니스 규칙을 소유** (Service는 조율만)

#### ⑤ Adapter — Port 구현 (MyBatis)

```java
@Component  // ← Spring Bean으로 등록
public class PayMeansRepositoryAdapter implements PayMeansRepositoryPort {
    private final PayMeansMapper mapper;  // MyBatis 매퍼
    
    // Spring이 MyBatis 매퍼를 주입
    public PayMeansRepositoryAdapter(PayMeansMapper mapper) {
        this.mapper = mapper;
    }
    
    @Override
    public PayMeans save(PayMeans payMeans) {
        // 1. 도메인 객체 → Entity 변환
        PayMeansEntity entity = PayMeansEntity.from(payMeans);
        
        // 2. 채번 (여기서 번호 생성)
        entity.setPayMeansNo(generatePayMeansNo());
        
        // 3. MyBatis로 INSERT
        mapper.insert(entity);
        
        // 4. 채번된 번호를 도메인 객체에 반영해서 반환
        return payMeans.withAssignedNo(entity.getPayMeansNo());
    }
    
    private Long generatePayMeansNo() {
        return Long.parseLong(
            "3" + String.format("%09d", ThreadLocalRandom.current().nextInt(0, 1_000_000_000))
        );
    }
}
```

**Adapter의 책임:**
- 도메인 객체(`PayMeans`) ↔ Entity(`PayMeansEntity`) 변환
- MyBatis Mapper 호출
- 채번 로직 (인프라 관심사)
- **도메인은 DB 기술을 몰라도 됨**

#### ⑥ MyBatis Mapper — SQL 실행

```java
@Mapper  // ← MyBatis가 구현체 자동 생성
public interface PayMeansMapper extends BaseMapper<PayMeansEntity> {
    // BaseMapper가 기본 CRUD 제공 (insert, selectById, update, delete)
}
```

**MyBatis-Plus `BaseMapper`:**
- XML 없이 기본 CRUD 자동 생성
- `mapper.insert(entity)` → `INSERT INTO PAY_MEANS ...` 자동 실행
- Entity의 `@TableName`, `@TableId` 어노테이션 보고 SQL 생성

```java
@TableName("PAY_MEANS")
public class PayMeansEntity {
    @TableId(type = IdType.INPUT)
    private Long payMeansNo;
    
    private String tenantId;
    private Long ownerCustomerNo;
    // ...
}
```

#### ⑦ AOP — 공통 관심사 (등록자/변경자 자동 채움)

```java
@Component
public class MybatisPlusConfig implements MetaObjectHandler {
    
    @Override
    public void insertFill(MetaObject metaObject) {
        // INSERT 시 자동 채움
        this.strictInsertFill(metaObject, "firstRegistrId", String.class, "P215138");
        this.strictInsertFill(metaObject, "firstRegistDtm", LocalDateTime.class, LocalDateTime.now());
    }
    
    @Override
    public void updateFill(MetaObject metaObject) {
        // UPDATE 시 자동 채움
        this.strictUpdateFill(metaObject, "finalChgrId", String.class, "P215138");
        this.strictUpdateFill(metaObject, "finalChgDtm", LocalDateTime.class, LocalDateTime.now());
    }
}
```

**Spring AOP:**
- MyBatis-Plus가 INSERT/UPDATE 실행 직전에 이 핸들러 호출
- Entity의 `@TableField(fill = FieldFill.INSERT)` 필드를 자동 채움
- **Service 코드에서 등록자/변경자 세팅할 필요 없음**

## 4. Spring Boot 에코시스템

### 4.1 application.yml — 설정 중앙 관리

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/nova_db
    username: P215138
    password: park2019**
    driver-class-name: com.mysql.cj.jdbc.Driver
  
mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true  # DB snake_case → Java camelCase
  
autopay:
  vault:
    aes-key: autopay-demo-key-1234  # 커스텀 설정 (금고 암호화 키)
```

**Spring이 하는 일:**
- `spring.datasource.*` → HikariCP 커넥션 풀 자동 구성
- `mybatis-plus.*` → MyBatis 설정 자동 구성
- `@Value("${autopay.vault.aes-key}")` → Java 코드에서 주입 가능

### 4.2 Profile — 환경별 설정

```
application.yml             공통
application-dev.yml         개발
application-prod.yml        운영
```

실행 시:
```bash
java -jar app.jar --spring.profiles.active=prod
```
→ `application.yml` + `application-prod.yml` 병합

### 4.3 @ConfigurationProperties — 타입 안전한 설정

```java
@Component
@ConfigurationProperties(prefix = "autopay.vault")
public class VaultProperties {
    private String aesKey;
    
    public String getAesKey() { return aesKey; }
    public void setAesKey(String aesKey) { this.aesKey = aesKey; }
}

// 사용
@Component

    private final VaultProperties properties;
    
    public AccountVaultAdapter(VaultProperties properties) {
        this.aesKey = properties.getAesKey();
    }
}
```

**장점:**
- `@Value("${autopay.vault.aes-key}")` 여러 곳에 쓰는 것보다 중앙 관리
- IDE가 자동완성 지원
- 타입 안전 (String, Integer 등 자동 변환)

## 5. 멀티모듈 구조 — Gradle

```
autopay/
├── app/           도메인 로직
├── boot/          Spring Boot 진입점, 설정
├── contract/      API 계약 (다른 컴포넌트가 사용)
├── client-rest/   외부 REST 연동
└── client-message/ MQ 연동
```

### 5.1 모듈 의존성 규칙

```
boot → app → contract
boot → client-rest → contract
boot → client-message → contract
```

- `boot`가 최종 실행 가능한 JAR 생성
- `contract`는 순수 인터페이스 (구현체 없음)
- `app`은 `contract`를 구현
- `client-rest`, `client-message`는 외부 연동 Adapter

### 5.2 build.gradle 핵심

```gradle
// boot/build.gradle
dependencies {
    implementation project(':app')
    implementation project(':client-rest')
    implementation 'org.springframework.boot:spring-boot-starter-web'
}

// app/build.gradle
dependencies {
    api project(':contract')  // contract를 외부에 노출
    implementation 'org.springframework.boot:spring-boot-starter-data-jdbc'
    implementation 'com.baomidou:mybatis-plus-boot-starter:3.5.5'
}
```

**`api` vs `implementation`:**
- `api`: 이 모듈을 의존하는 쪽도 해당 라이브러리 사용 가능
- `implementation`: 이 모듈 내부에서만 사용

```java
@SpringBootTest  // ← Spring 컨테이너 전체 띄우고 테스트
```

## 7. 핵심 정리 — Spring Boot가 해주는 것

| 일반 자바 | Spring Boot |
|----------|-------------|
| `new Service()` 직접 생성 | `@Autowired` 자동 주입 |
| 생성 순서 고민 | 의존성 그래프 자동 해결 |
| 싱글톤 패턴 직접 구현 | `@Component` 자동 싱글톤 |
| `try-catch-rollback` | `@Transactional` 선언적 트랜잭션 |
| Servlet 코드 작성 | `@RestController` 자동 HTTP 핸들링 |
| JSON 파싱 코드 | `@RequestBody` 자동 역직렬화 |
| DB 커넥션 풀 설정 | `spring.datasource.*` 자동 구성 |
| 환경별 설정 분기 | `@Profile`, `application-{env}.yml` |
