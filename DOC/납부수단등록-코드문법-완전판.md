# 납부수단 등록: 자바 초보자를 위한 코드 문법 완전판

> 대상: 자바를 처음 배우는 개발자
> 방식: 모든 코드를 한 줄씩, 기초 문법(public, static, new, = 등)까지 전부 설명
> 목표: "이 코드가 왜 이렇게 쓰였는지, 문법적으로 무슨 뜻인지" 완전 이해

---

## 0. 전체 흐름 요약

```
화면 → Controller → Service → Port → Adapter → DB
       (접수)     (업무 흐름)  (문)   (실제 기술)
```

납부수단 등록은 **본인 등록(registerByOwner)** 하나만 깊게 파고듭니다.

---

## 1. 컨트롤러 — 요청을 받는 창구

### 전체 코드

```java
@RestController
@RequestMapping("/api/autopay/pay-means")
public class PayMeansCoreApiController {

    private final PayMeansRegistrationService registrationService;

    public PayMeansCoreApiController(PayMeansRegistrationService registrationService) {
        this.registrationService = registrationService;
    }

    @PostMapping
    public PayMeansResult register(@RequestBody RegisterPayMeansCommand command) {
        return registrationService.registerByOwner(command);
    }
}
```

### 한 줄씩 문법 설명

#### `@RestController`
- `@`로 시작하는 것 = **어노테이션(annotation)**. 자바 컴파일러나 스프링에게 "이 클래스는 이런 용도야"라고 알려주는 표시입니다.
- `@RestController` = "이 클래스는 REST API 요청을 받는 컨트롤러야"라는 뜻.

#### `@RequestMapping("/api/autopay/pay-means")`
- 이 컨트롤러가 담당하는 URL 경로를 지정합니다.
- 화면에서 `POST /api/autopay/pay-means`로 요청 오면 이 클래스가 처리합니다.

#### `public class PayMeansCoreApiController {`
- `public` = 접근 제어자. "어디서나 접근 가능"이란 뜻. (다른 패키지에서도 쓸 수 있음)
- `class` = 클래스 선언. 자바의 기본 단위.
- `PayMeansCoreApiController` = 클래스 이름. 관례상 대문자로 시작.
- `{` = 클래스 몸통 시작.

#### `private final PayMeansRegistrationService registrationService;`
- `private` = "이 클래스 안에서만 접근 가능". 바깥에서 `controller.registrationService` 못 함.
- `final` = "한 번 정해지면 못 바꿈". 생성자에서 넣은 뒤 변경 불가.
- `PayMeansRegistrationService` = 타입(클래스명).
- `registrationService` = 변수 이름.
- `;` = 자바 문장의 끝.

#### 생성자
```java
public PayMeansCoreApiController(PayMeansRegistrationService registrationService) {
    this.registrationService = registrationService;
}
```
- 생성자 = 클래스 이름과 똑같은 이름의 메서드. `new` 할 때 자동 실행.
- `(PayMeansRegistrationService registrationService)` = 파라미터. "이 클래스를 만들 때 `PayMeansRegistrationService` 타입 객체를 넣어줘"
- `this.registrationService` = "이 객체의 registrationService 필드"
- `=` = 대입. 오른쪽 값을 왼쪽 변수에 넣음.
- `registrationService` (오른쪽) = 파라미터로 받은 것.
- 즉, "파라미터로 받은 서비스 객체를 내 필드에 보관"하는 코드.

#### `@PostMapping`
- "POST 요청이 오면 아래 메서드를 실행해라"

#### 메서드
```java
public PayMeansResult register(@RequestBody RegisterPayMeansCommand command) {
    return registrationService.registerByOwner(command);
}
```
- `public` = 어디서나 접근 가능.
- `PayMeansResult` = 반환 타입. 이 메서드는 `PayMeansResult` 객체를 돌려줌.
- `register` = 메서드 이름.
- `(@RequestBody RegisterPayMeansCommand command)` = 파라미터. `@RequestBody`는 "화면에서 보낸 JSON을 자동으로 `RegisterPayMeansCommand` 객체로 바꿔서 넣어줘"라는 뜻.
- `return` = "이 값을 메서드 결과로 돌려줌"
- `registrationService.registerByOwner(command)` = `registrationService` 객체의 `registerByOwner` 메서드를 호출하고 그 결과를 반환.
  - `.` (점) = "객체의 필드나 메서드에 접근"
  - `()` = 메서드 호출. 괄호 안에 파라미터 넣음.

## 2. Command — 입력 상자 (record)

```java
public record RegisterPayMeansCommand(
        String tenantId,
        String customerNo,
        String payMeansTypeCd,
        String payMeansNm,
        String fincInstCd,
        String accountOrCardNo,
        String holderNm,
        String cardValidYymm
) {
}
```

### 한 줄씩 문법 설명

#### `public record RegisterPayMeansCommand(`
- `public` = 어디서나 접근 가능.
- `record` = 자바 14+에서 추가된 특별한 클래스. "값만 담는 불변 상자"를 간단히 만드는 문법.
- `RegisterPayMeansCommand` = 이름.
- `(` = 괄호 안에 필드 나열.

#### 필드들
```java
String tenantId,
String customerNo,
...
```
- `String tenantId` = "String 타입의 tenantId 필드". 각 줄이 하나의 필드.
- `,` = 필드 구분.

#### `record`의 자동 생성 기능
`record`를 선언하면 자바가 자동으로 만들어주는 것들:
1. 생성자: `new RegisterPayMeansCommand("SKT", "900...", ...)`
2. getter: `command.tenantId()` — `()` 붙여서 부름. 일반 클래스의 `getTenantId()`와 비슷.
3. `equals`, `hashCode`, `toString` 메서드.

setter는 **없습니다.** `record`는 불변이라 한 번 만들면 값 변경 불가.

## 3. Service 생성자 — 6개 포트 주입

```java
@Service

    private final SmsAuthGatewayPort smsAuth;
    private final PayMeansRepositoryPort payMeansRepository;
    private final AgentPayMapRepositoryPort agentPayMapRepository;
    private final RealtmAuthHistoryPort realtmAuthHistory;
    private final AccountVaultPort accountVault;

    public PayMeansRegistrationService(
            FinancialAuthGatewayPort financialAuth,

        this.accountVault = accountVault;
```

### 한 줄씩 문법 설명

#### `@Service`
- 스프링에게 "이 클래스를 서비스로 관리해. 앱 시작 시 객체 하나 만들어 보관해"

#### 필드 6개
```java
private final FinancialAuthGatewayPort financialAuth;
```
- `private` = 이 클래스 안에서만 접근.
- `final` = 한 번 정하면 못 바꿈.
- `FinancialAuthGatewayPort` = 타입. **인터페이스** 타입입니다. 실제로는 구현체(어댑터)가 들어옴.
- `financialAuth` = 변수 이름.

나머지 5개도 똑같은 패턴.

#### 생성자
```java
public PayMeansRegistrationService(
        FinancialAuthGatewayPort financialAuth, ...
```
- 생성자 = 클래스명과 같은 이름.
- 파라미터 6개를 받습니다. 각각 인터페이스 타입.

#### 생성자 몸통
```java
this.financialAuth = financialAuth;
```
- `this.financialAuth` = "이 객체의 financialAuth 필드"
- `=` = 대입.
- `financialAuth` (오른쪽) = 파라미터로 받은 것.
- "파라미터로 받은 것을 내 필드에 저장". 나머지 5줄도 동일.

**중요**: 스프링이 앱 시작 시 이 생성자를 보고 "아, 6개 포트가 필요하구나" → 각 포트를 구현한 어댑터를 찾아서 자동으로 넣어줍니다. 이게 "의존성 주입(DI)".

## 4. registerByOwner 메서드 — 단계별 한 줄씩

### 메서드 선언부

```java
@Transactional

```

#### `@Transactional`
- "이 메서드 안의 모든 DB 작업을 하나의 트랜잭션으로 묶어라. 성공하면 전부 커밋, 중간에 예외 나면 전부 롤백"

#### `public PayMeansResult registerByOwner(RegisterPayMeansCommand cmd) {`
- `public` = 어디서나 접근 가능.
- `PayMeansResult` = 반환 타입. 등록 결과를 담은 객체를 돌려줌.
- `registerByOwner` = 메서드 이름.
- `(RegisterPayMeansCommand cmd)` = 파라미터. `cmd`라는 변수로 받음.

---

### 단계 ①: 유형 코드를 enum으로 변환

```java
PayMeansType type = PayMeansType.fromCode(cmd.payMeansTypeCd());
```

#### 문법 분해
- `PayMeansType` = 타입. enum 타입.
- `type` = 변수 이름.
- `=` = 대입.
- `PayMeansType.fromCode(...)` = `PayMeansType` 클래스(enum)의 `fromCode` 메서드 호출.
  - 클래스명`.`메서드명 = **정적(static) 메서드** 호출. 객체 없이 바로 부름.
- `cmd.payMeansTypeCd()` = `cmd` 객체의 `payMeansTypeCd()` 메서드 호출. record의 getter. `"01"` 같은 문자열 반환.
- 즉, `"01"` 문자열을 `PayMeansType.BANK` enum 값으로 변환.

#### fromCode 내부 (참고)
```java
public static PayMeansType fromCode(String code) {
    for (PayMeansType t : values()) {
        if (t.code.equals(code)) return t;
    }
    throw new IllegalArgumentException("모르는 코드: " + code);
}
```
- `public static` = 정적 메서드. 객체 없이 클래스명으로 바로 부를 수 있음.
- `for (PayMeansType t : values())` = **향상된 for문**. `values()`는 enum이 자동 제공하는 메서드로 모든 값(BANK, CARD, SIMPLE_PAY) 배열을 반환. 그걸 하나씩 돌면서 `t`에 넣음.
- `if (t.code.equals(code))` = 조건문. `t.code`(예: "01")가 `code` 파라미터와 같으면 참.
- `return t;` = 찾은 enum 값을 반환하고 메서드 종료.
- `throw new ...` = 못 찾으면 예외를 던짐.

### PayMeans.registerByOwner 내부 — 가장 중요!

```java
public static PayMeans registerByOwner(String tenantId, String customerNo,
        PayMeansType type, String payMeansNm, String fincInstCd,
        Long bankacctCardAltrnateId, String holderNm) {
    
    PayMeans m = new PayMeans();
    m.tenantId = tenantId;
    m.customerNo = customerNo;
    m.type = type;
    m.payMeansNm = payMeansNm;
    m.fincInstCd = fincInstCd;
    m.bankacctCardAltrnateId = bankacctCardAltrnateId;
    m.holderNm = holderNm;
    m.status = PayMeansStatus.ACTIVE;
    m.changeReasonCd = "01";
    return m;
}
```

#### 한 줄씩 완전 분해

##### 첫 줄 — 메서드 선언
```java
public static PayMeans registerByOwner(String tenantId, ...
```
- `public` = 어디서나 접근 가능.
- `static` = **정적 메서드**. 객체 없이 `PayMeans.registerByOwner()`로 바로 호출 가능.
  - 왜 static? 아직 PayMeans 객체가 없는데 객체를 만드는 게 목적이니까. 객체가 있어야 부를 수 있다면 모순.
- `PayMeans` = 반환 타입. 이 메서드는 `PayMeans` 객체를 돌려줌.
- `registerByOwner` = 메서드 이름. 생성자(`new PayMeans()`) 대신 이 이름 있는 메서드로 만듦 → "정적 팩토리 메서드"
- `(String tenantId, ...)` = 파라미터 7개. 객체를 만들 때 필요한 값들.

##### 객체 생성
```java
PayMeans m = new PayMeans();
```
- `PayMeans` = 타입.
- `m` = 변수 이름. 임시로 `m`이라고 짧게 씀.
- `=` = 대입.
- `new PayMeans()` = **새 객체 생성**.
  - `new` = 자바의 객체 생성 키워드. 메모리에 객체 공간을 만듦.
  - `PayMeans()` = 생성자 호출. 괄호 안에 파라미터 넣음. 여기는 빈 생성자라 파라미터 없음.
- 즉, "빈 PayMeans 객체를 만들어 `m`에 저장"

##### 필드 채우기
```java
m.tenantId = tenantId;
```
- `m` = 방금 만든 객체.
- `.tenantId` = 그 객체의 `tenantId` 필드에 접근.
- `=` = 대입.
- `tenantId` (오른쪽) = 파라미터로 받은 값.
- 즉, "파라미터로 받은 tenantId를 객체의 tenantId 필드에 넣음"

나머지 줄도 똑같은 패턴:
```java
m.customerNo = customerNo;
m.type = type;
...
m.bankacctCardAltrnateId = bankacctCardAltrnateId;  // ← 계좌번호 아님! 대체ID!

```

##### 상태 강제 설정 — 핵심 규칙!
```java
m.status = PayMeansStatus.ACTIVE;
```
- `m.status` = 객체의 `status` 필드.
- `=` = 대입.
- `PayMeansStatus.ACTIVE` = enum 값. `PayMeansStatus`는 enum, `ACTIVE`는 그 안의 한 값.
- **핵심**: 본인 등록이면 상태를 무조건 `ACTIVE`(활성 10)로 설정. 이 규칙이 코드에 박혀있어, 누가 실수로 다른 상태로 만들 수 없음.

```java
m.changeReasonCd = "01";
```
- 변경사유코드도 `"01"`로 고정.

##### 반환
```java
return m;
```
- `return` = "이 값을 메서드의 결과로 돌려줌"
- `m` = 방금 만든 객체.
- 즉, "필드가 다 채워진 PayMeans 객체를 호출한 곳에 돌려줌"

##### 정리: 정적 팩토리 메서드를 쓰는 이유

생성자(`new PayMeans(...)`)로 만들면:
```java
PayMeans p = new PayMeans(tenantId, customerNo, ...);  // 상태를 뭘로 할지 모호
```
- 상태를 외부에서 정해야 함 → 실수로 잘못된 상태 가능.

정적 팩토리(`PayMeans.registerByOwner`)로 만들면:
```java
PayMeans p = PayMeans.registerByOwner(...);  // 이름만 봐도 "본인 등록"
```
- 상태가 자동으로 ACTIVE로 → 규칙 강제.
- 메서드 이름(`registerByOwner`, `registerByAgent`)으로 의도 명확.

## 5. 내부 메서드 — authenticateWithHistory

```java
private Long authenticateWithHistory(String tenantId, PayMeansType type, String fincInstCd,
                                     String accountOrCardNo, String holderNm, String cardValidYymm) {
    
    Long authSeq = realtmAuthHistory.createRequested(
            new RealtmAuthHistoryPort.RequestCommand(
                    tenantId, type.code(), authMethodOf(type), fincInstCd, accountOrCardNo));
    
    FinancialAuthGatewayPort.AuthResult result = financialAuth.authenticate(
            new FinancialAuthGatewayPort.AuthCommand(
                    tenantId, type.code(), fincInstCd, accountOrCardNo, holderNm, cardValidYymm));
    
    realtmAuthHistory.applyResult(authSeq, tenantId, result.success(),
            result.externalAuthKey(), result.resultCode(), result.resultMessage());
    
    if (!result.success()) {
        throw new IllegalStateException(
                "실시간인증 실패: " + result.resultCode() + " " + result.resultMessage());
    }
    return authSeq;
}
```

### 한 줄씩 문법

#### 인증이력 생성
```java
Long authSeq = realtmAuthHistory.createRequested(
        new RealtmAuthHistoryPort.RequestCommand(...));
```
- `Long authSeq` = 변수 선언.
- `realtmAuthHistory.createRequested(...)` = 메서드 호출.
- `new RealtmAuthHistoryPort.RequestCommand(...)` = 파라미터. 새 객체 생성.
  - `RealtmAuthHistoryPort.RequestCommand` = **포트 인터페이스 안에 선언된 record**.
  - `포트명.record명` = 중첩 타입 접근. `.`으로 구분.
  - `record`는 클래스라 `new`로 만듦.
- 즉, "인증이력 INSERT → 순번 반환 → authSeq에 저장"

#### 금융기관 인증
```java
FinancialAuthGatewayPort.AuthResult result = financialAuth.authenticate(...);
```
- `FinancialAuthGatewayPort.AuthResult` = 타입. 역시 포트 안의 중첩 record.
- `result` = 변수.
- `financialAuth.authenticate(...)` = 인증 메서드 호출. 실제로는 `FinancialAuthStubAdapter` 실행.
- `new FinancialAuthGatewayPort.AuthCommand(...)` = 파라미터 객체.

#### 결과 반영
```java
realtmAuthHistory.applyResult(authSeq, tenantId, result.success(), ...);
```
- `result.success()` = `result` 객체의 `success()` 메서드. boolean 반환. record의 getter.
- `result.externalAuthKey()` = 마찬가지.
- 인증 성공/실패 모두 이력에 UPDATE.

#### 실패 시 예외
```java
if (!result.success()) {
    throw new IllegalStateException(...);
}
```
- `!` = NOT 연산자. `result.success()`가 false이면 `!false = true` → if 실행.
- `throw new IllegalStateException(...)` = 예외 던짐.
- 예외가 던져지면 이 메서드 실행 중단 → 호출한 곳(registerByOwner)도 중단 → `@Transactional`이 롤백.

#### 성공 시 반환
```java
return authSeq;
```
- 인증 순번 반환.

## 6. switch expression — authMethodOf

```java
private String authMethodOf(PayMeansType type) {
    return switch (type) {
        case BANK       -> "01";
        case CARD       -> "02";
        case SIMPLE_PAY -> "05";
    };
}
```

### 한 줄씩 문법

#### `return switch (type) {`
- `return` = 결과를 반환.
- `switch (type)` = type 값에 따라 분기.
- `{` = switch 몸통 시작.

#### `case BANK -> "01";`
- `case` = 경우.
- `BANK` = `PayMeansType` enum의 한 값.
- `->` = "이 경우엔 이 값을 반환". 자바 14+의 **switch expression** 문법.
- `"01"` = 반환할 값.
- `;` = case 끝.

#### `};`
- `}` = switch 끝.
- `;` = return 문장 끝.

**기존 방식과 비교**:
```java
// 옛날 방식
String method;
switch (type) {
    case BANK:
        method = "01";
        break;
    case CARD:
        method = "02";
        break;
    default:
        method = "05";
}
return method;
```
- `break`가 필요하고 길다.
- switch expression은 바로 값을 반환하니 간결.

## 8. 자바 기초 문법 완전 정리

| 문법 | 뜻 | 예시 |
|------|-----|------|
| `public` | 어디서나 접근 가능 | `public class X` |
| `private` | 이 클래스 안에서만 | `private String name` |
| `static` | 객체 없이 클래스명으로 바로 호출 | `PayMeans.registerByOwner()` |
| `final` | 한 번 정하면 못 바꿈 | `private final String id` |
| `class` | 클래스 선언 | `public class PayMeans` |
| `record` | 값만 담는 불변 상자 | `public record Command(...)` |
| `enum` | 정해진 값 목록 | `enum Status { ACTIVE, SUSPENDED }` |
| `new` | 객체 생성 | `new PayMeans()` |
| `.` (점) | 객체의 필드/메서드 접근 | `payMeans.getStatus()` |
| `=` | 대입 | `int x = 10;` |
| `==` | 같은지 비교 | `if (x == 10)` |
| `!=` | 다른지 비교 | `if (x != 10)` |
| `!` | NOT, 반대 | `if (!success)` |
| `&&` | AND, 둘 다 참 | `if (a && b)` |
| `||` | OR, 하나만 참 | `if (a || b)` |
| `()` | 메서드 호출, 파라미터 | `save(payMeans)` |
| `{}` | 블록, 묶음 | `if (...) { ... }` |
| `;` | 문장 끝 | `int x = 10;` |
| `return` | 메서드 결과 반환 | `return m;` |
| `throw` | 예외 던지기 | `throw new Exception()` |
| `if` | 조건문 | `if (조건) { ... }` |
| `for` | 반복문 | `for (int i=0; i<10; i++)` |
| `switch` | 분기문 | `switch (x) { case 1 -> ... }` |
| `this` | 이 객체 자신 | `this.name = name;` |
